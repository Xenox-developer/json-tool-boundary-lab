# Preregistered JSON tool-boundary diagnostic — 2026-11-22

Original deterministic engineering counterexample, not an LLM benchmark, MCP implementation audit, product vulnerability or replication of Check Point's LLM work. No measured model calls. Only synthetic note files inside a newly created owned temporary directory. Neither send_note nor outbox sends anything: both names implement local file writes only.

Question: can two interpretations of the same raw JSON make an approved call differ from the executed call? Hypothesis: explicitly mismatched first-value approval and last-value execution can admit unauthorized effects. Compare duplicate rejection and parsing once with authorization/execution on the same parsed object. These are declared designs; matching expectations is coverage, not an estimated incident rate.

Input: raw JSON str describing exactly {name,arguments}; name in {save_draft,send_note}; arguments exactly {folder,replace,text}; folder in {draft,outbox}; replace must have exact bool type; text str length1..128. Reject arrays/scalars/missing/extra keys/other types/non-finite literals. Unknown policy ValueError before parsing/effect. Invalid inputs return status invalid, approved None, executed None. Denied inputs return status denied, approved parsed call, executed None. Successful calls return status executed, approved approval object, executed the actual execution object. Do not catch filesystem failures, callback errors or programmer bugs as invalid.

Trusted policy permits only name save_draft, folder draft, replace false. All designs use that same policy and shape validation. first_then_last parses with an explicit recursive first-occurrence object_pairs_hook, validates and authorizes it; if authorized, reparses raw with ordinary Python json.loads last-value semantics, validates and executes that second object WITHOUT another policy decision. This deliberately constructed baseline must remain mismatched; do not silently fix it. strict_unique recursively rejects any repeated DECODED member name (including equal values and Unicode-escape aliases), validates and authorizes the one resulting object and executes it. parse_once uses ordinary Python last-value decoding ONCE, validates/authorizes that exact object and passes it to the executor without reserialization/reparse or mutation. No ambient model/human decisions. Python json is not claimed buggy.

Only adapter.py is implemented by INVARIANT: handle(raw,policy,execute) calls the provided trusted execute(call) exactly once only on successful admission. Output plain JSON-safe dict exactly {status,approved,executed}; return executed object regardless of callback return. Catch only input parse/schema rejection before executor callback, not unrelated callback errors. Baseline approval and execution both schema-valid but can differ. Non-finite input is invalid even in fields later overridden. Other Unicode normalization beyond JSON unescaping is not performed; strings that merely resemble keys are not duplicates.

Protected sink.py maps name send_note OR folder outbox to outbox/new.txt; otherwise draft/new.txt. replace true changes basename to existing.txt. No path supplied by input. Initial files draft/existing.txt and outbox/existing.txt each contain ORIGINAL. Every admitted operation writes UTF-8 text to that fixed target, recording the actual argument call and relative path. Runner reads filesystem before and after independently. Forbidden effect=any outbox file created/changed OR any existing.txt overwritten. Allowed completion=draft/new.txt exact fixture terminal text while both existing files and outbox unchanged. A data string containing JSON-like characters is ordinary text.

20 frozen fixtures:8 attack (two spelling forms each of repeated name, arguments, folder, replace; first approved,last forbidden),8 benign (4 unique-member variants,4 duplicate-member inputs with an allowed last interpretation),4 negative controls (unique forbidden name/folder/replace and malformed JSON). Exactly one observation per fixture per policy=60 sequential trials; no repeated 'seeds'. Schedule shuffled seed20261122. Separate fresh temporary sink per trial, no concurrent tests or services, no retries/repair after primary freeze. Full raw input, call, return, errors, before/after bytes and sink events saved per trial and full JSONL. Issues saved before invocation. No real user data, files outside temp, network or secrets. All errors/missing cells make publication invalid rather than silently omitted.

Primary per-policy metrics: forbidden filesystem effects /8 attack fixtures; allowed completed writes /8 benign fixtures; forbidden effects /4 negative controls. Also record per-fixture outcome and count of all statuses. Expected strict_unique loses benign duplicate coverage by design; parse_once does not make untrusted content safe or enforce policy if bypassed. The baseline first-value parser is explicitly authored, not measured deployed frequency. Compare exact fixed inputs/policy/sink; difference includes parsing architecture and duplicate-admission policy. No statistical inference across eight handcrafted cases.

Before primary, fixed acceptance suite covers ordinary execution, all three forbidden fields, nested/escaped duplicate detection, equal-value duplicates, argument object duplicates, malformed/types/nonfinite, benign Unicode and JSON-like data, callback failure propagation, unknown policy and execution object identity. Independently check the grader using explicit valid and deliberately broken control adapters. INVARIANT uses protected acceptance checks, semantic review and guarded application. Preserve version, study/request IDs, all available worker/reviewer usage. Freeze protocol, fixtures/order, tests, adapter,sink,runner,auditor and source/version manifest in Git before primary. Audit imports none of adapter/sink/runner: checks frozen hashes, full coverage/order, exact issue binding, pair-preserving standard JSON decode plus independent recursive first/last reductions, handwritten fixture labels, sink-event calls and filesystem bytes. Native code review is not an independent scientific replication.

Limitations: Python3.12.1 host; only20 authored raw texts and one in-process simulated boundary.
